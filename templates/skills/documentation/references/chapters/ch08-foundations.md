# Chapter 8: Foundations

## Core Idea

Diátaxis works because it maps documentation onto the structure of craft itself: two dimensions - action/cognition and acquisition/application - define the complete territory of skill, which is why there are exactly four kinds of documentation, not three or five.

## Frameworks Introduced

- **The two dimensions of craft**:
  - **Action/cognition**: a skill contains both action (practical knowledge, knowing _how_, what we do) and cognition (theoretical knowledge, knowing _that_, what we think). Completely bound up with each other, yet wholly distinct counterparts - two aspects of the same thing.
  - **Acquisition/application**: a practitioner's craft must be both acquired and applied. Being "at work" (applying skill and knowledge) and being "at study" (acquiring them) are again counterparts, distinct but bound together.
- **The map of the territory of craft**: laying the two dimensions out gives a complete map. The dimensions don't just cover the territory, they _define_ it - which is why there are necessarily four quarters, and could not be three or five. Not an arbitrary number.
- **Serving needs**: applying "documentation must serve the needs of its users" to the map yields the four forms:

  | need          | addressed in  | the user             | the documentation |
  | ------------- | ------------- | -------------------- | ----------------- |
  | learning      | tutorials     | acquires their craft | informs action    |
  | goals         | how-to guides | applies their craft  | informs action    |
  | information   | reference     | applies their craft  | informs cognition |
  | understanding | explanation   | acquires their craft | informs cognition |

## Key Concepts

- **The practitioner in a domain of skill**: the user Diátaxis serves. A domain of skill is defined by a craft - using a tool or product is a craft, as is a whole discipline or profession: using a programming language, flying a particular aircraft, being a pilot in general.
- **Theory over heuristic**: without a foundation, Diátaxis would be "just another useful heuristic approach", its strongest claim "it seems to work quite well". The theory shows _why_ it works.
- **Complete enumeration**: tutorials, how-to guides, reference, and explanation completely enumerate the documentation types that serve practitioners of a craft - "there is simply no other territory to cover".

## Mental Models

- When someone proposes a fifth documentation type (or wants to merge two), test it against the dimensions: which quadrant's need does it serve? A "new" type is a subdivision, a rename, or a blur - the territory admits only four quarters.
- A map is only reliable if it adequately describes a reality; the Diátaxis map is underpinned by a systematic description of generalised user needs, not by convention.

## Anti-patterns

- **Treating the four types as an arbitrary taxonomy**: they are derived, not invented; schemes that are mere lists invite the question "why this list rather than another?" (see ch09).

## Worked Example

Why "FAQ" is not a fifth kind: take a typical FAQ entry - "Why does the build fail on ARM?" Ask the compass questions. The answer informs cognition (it's knowledge, not steps) and serves application (the user hit this at work) - so it is reference material, or, if it discusses design trade-offs, explanation. Every FAQ entry decomposes this way into one of the four quarters; "FAQ" is a presentation format, not a need, and the territory stays fully covered by four.

## Key Takeaways

1. Documentation must serve user needs; user needs decompose along exactly two dimensions - action/cognition and acquisition/application.
2. Four quadrants follow necessarily: learning, goals, information, understanding.
3. Use the dimensions, not the labels, when classifying odd content: the labels are quadrant names, the dimensions are the test.
4. The completeness claim is the practical payoff: any documentation content has exactly one home.
